из конкретного архива, а не подтверждение измерений или актуальности набора у организаторов.

## Что сообщил коллега

В переданном пользователем сообщении описана другая версия, где эти 81 значения
равны нулю, а остальные поля совпадают. Указанные отчёт и CSV находятся на другом
компьютере (`C:/Users/Asus/...`); содержимое этих файлов в данной проверке недоступно.
Поэтому полное совпадение остальных полей и число отличий между двумя версиями здесь
не подтверждены независимо. Изменение 81 значения объясняло бы 2 + 81 = 83 нуля,
но это не основание самостоятельно создавать такую версию train.

Ни 10000, ни альтернативный ноль не признаны правильной меткой. Не установлено,
где, когда и почему значения появились до создания архива. Совпадение с пропусками
согласуется с гипотезой обработки пропусков, но не доказывает конкретный механизм.

## Последствия для модели

81 строка составляет 25,3125% train. Двухэтапная v4 использует порог SI >= 10000;
часть выигрыша может быть связана с механизмом подготовки меток. IC50, CC50 и их
пропуски не передаются модели: проверка пропусков существует только в отдельном аудите.

Старые MSE арифметически остаются результатами на сохранённых метках. Сравнение v3
и v4 использует одну версию train, но его нельзя представлять как подтверждённое
улучшение прогноза измеренного SI. MSE на версии с 83 нулями напрямую с ним не сравнивается.
Удаление спорных строк, подстановка нулей или выбор версии с меньшим MSE не выполнены.
Остальные 239 строк также не объявляются медицински проверенными.

Прогнозы доступны для исследования с явным статусом `unresolved_target_semantics`.
Статус связан с SHA-256 train, присутствует в API, пакетном CSV и метаданных CLI.
Для новой неизвестной версии используется `not_reviewed`. Перед заимствованием OOF
из другого запуска проверяются версия и хеши train/test/sample; разные наборы отклоняются.
Исторические отчёты, модели и снимки кода не переписаны.

## Воспроизведение

Из корня проекта, в установленном окружении:

```powershell
.venv\Scripts\python.exe -X utf8 scripts/audit_target_provenance.py --archive data/source_archives/hakathonMiphi.zip --output .artifact-work/target-check
```

После получения второго файла можно добавить `--other-train путь/к/train.csv` и
выбрать новый каталог `--output`. Проверка сопоставляет записи по всем нетаргетным
полям, допускает другой порядок строк и останавливается при неоднозначных дубликатах
или отличиях остальных полей. Она ничего не импортирует и не исправляет.

## Проверка исправлений

59 тестов прошли: в том числе несовпадение архивов, перемешанный порядок строк,
изменение нетаргетных полей, неоднозначные дубликаты, смена хеша при прежнем имени
версии, отсутствие хеша и передача статуса в CSV. Предупреждения в тестах относятся
к устаревающим API matplotlib/pyparsing, падений нет.

API и CSV сохранили прогнозы всех 597 test-строк в пределах машинной точности;
проверен пакет из 2000 строк. В браузере на 1440/390 px пройдены все три экрана,
ошибки ввода, пагинация, выгрузка статуса и скачивание 81 строки; ошибок JavaScript
и горизонтального переполнения страницы нет. Проверка браузера сначала остановилась
на старом ожидании заголовка «Новая модель»; ожидание обновлено под исторический статус,
после чего полный сценарий прошёл.

Механический UI-детектор указал на скрытое изображение до получения прогноза,
утверждённую палитру и существующие размеры шрифта. Изображение после расчёта
загружается, новые элементы используют текущую палитру и размеры. Desktop/mobile
снимки просмотрены; новый статус и элементы управления читаемы.
